## 12.1 Два вида ошибок

В уроке 5 вводного курса вы научились читать сообщения об ошибках. Ошибки в Python бывают примерно двух видов:

1. **Синтаксические ошибки** (`SyntaxError`, `IndentationError`): код не соответствует грамматике Python, и **программа даже не начинает работать**. Помочь может только исправление кода.
2. **Исключения** (exception): грамматика в порядке, но **при выполнении какой-то строки что-то пошло не так** — деление на 0, превращение `"abc"` в целое число, открытие несуществующего файла…

```python norun
age = int(input("Сколько вам лет? "))     # пользователь ввёл «двенадцать»
print(age + 1)
```

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    age = int(input("Сколько вам лет? "))
ValueError: invalid literal for int() with base 10: 'двенадцать'
```

`ValueError` здесь — это исключение. По умолчанию исключение **сразу останавливает программу** и печатает трассировку (traceback). Но многие исключения предсказуемы (пользователи всегда ошибаются при вводе), и хочется, чтобы программа **обрабатывала их сама**, а не падала.

## 12.2 `try / except`: перехватываем исключение

```python input="двенадцать"
text = input("Сколько вам лет? ")
try:
    age = int(text)                      # код, который может упасть, — внутри try
    print("В следующем году вам будет", age + 1)
except ValueError:                       # если случилась ValueError, выполняется это
    print(f"«{text}» — не целое число; введите цифрами, например 12")
print("программа продолжает работу")
```

Как это работает:

1. сначала выполняется код внутри `try`;
2. если **ничего** не сломалось, часть `except` пропускается;
3. если случилась `ValueError`, остаток блока `try` **пропускается**, и выполнение переходит в `except ValueError:`;
4. в любом случае код после этого продолжает выполняться.

Частый приём — **спрашивать, пока ввод не станет правильным**:

```python input="abc\n-5\n12"
while True:
    try:
        age = int(input("Введите возраст: "))
        if age < 0:
            print("возраст не может быть отрицательным")
            continue
        break                                # ввод правильный — выходим из цикла
    except ValueError:
        print("введите целое число")
print("ваш возраст:", age)
```

## 12.3 Перехватываем разные исключения

Фрагмент кода может вызвать исключения разных видов, и каждое можно обработать отдельно:

```python
def divide(a_text, b_text):
    try:
        a, b = float(a_text), float(b_text)
        return a / b
    except ValueError:
        return "введите числа"
    except ZeroDivisionError:
        return "делитель не может быть 0"

print(divide("10", "4"))
print(divide("10", "abc"))
print(divide("10", "0"))
```

Чтобы обработать несколько исключений одинаково, перечислите их в кортеже: `except (ValueError, ZeroDivisionError):`.

### Подробности: `as e`

```python
try:
    nums = [1, 2, 3]
    print(nums[10])
except IndexError as e:
    print("ошибка:", e)                 # e — объект исключения; при печати выводится сообщение об ошибке
    print("тип исключения:", type(e).__name__)
```

## 12.4 `else` и `finally`

Полная конструкция выглядит так:

```python
def read_number(text):
    try:
        n = int(text)
    except ValueError:
        print(f"  «{text}»: не целое число")
    else:                               # выполняется, только если в try ошибок не было
        print(f"  «{text}»: получено {n}")
    finally:                            # выполняется всегда, в самом конце
        print("  — готово")

read_number("42")
read_number("4.2")
```

- `else` выполняется, только если **исключения не было**. Если поместить сюда «то, что не нужно делать после ошибки», а не запихивать это в `try`, то `try` будет охватывать лишь одну-две строки, которые действительно могут упасть.
- `finally` **выполняется всегда**, даже если в `try` есть `return` или возникло исключение, которое никто не перехватил. Его используют для «уборки» — закрыть файлы, сетевые соединения. (Файлы, открытые через `with`, закрываются сами, так что нужен он реже.)

## 12.5 Вызываем исключения сами: `raise`

Если в вашу функцию передали неразумные аргументы, лучше всего не печатать сообщение и не возвращать странное значение, а **вызвать исключение**, чтобы вызывающий узнал о проблеме:

```python
def set_age(age: int) -> int:
    if not 0 <= age <= 150:
        raise ValueError(f"возраст должен быть от 0 до 150, получено {age}")
    return age

for a in (12, -3, 200):
    try:
        print("установлено:", set_age(a))
    except ValueError as e:
        print("не удалось:", e)
```

`raise ТипИсключения("сообщение")` сразу останавливает текущую функцию и передаёт исключение тому, кто её вызвал; если его так никто и не перехватит, программа остановится и напечатает трассировку.

### Собственные исключения

Можно определять свои типы исключений, чтобы смысл ошибки был понятнее (`class` подробно — в следующем уроке, пока просто повторите образец):

```python
class InsufficientFunds(Exception):     # наследуется от Exception
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFunds(f"на счёте {balance} руб., нельзя снять {amount} руб.")
    return balance - amount

try:
    print(withdraw(100, 30))
    print(withdraw(100, 300))
except InsufficientFunds as e:
    print("снятие не удалось:", e)
```

## 12.6 Частые типы исключений

| Исключение | Когда возникает | Пример |
|------------|-----------------|--------|
| `ValueError` | тип правильный, значение неподходящее | `int("abc")` |
| `TypeError` | неправильный тип | `"1" + 1` |
| `ZeroDivisionError` | деление на 0 | `5 / 0` |
| `IndexError` | индекс за пределами | `[1, 2][5]` |
| `KeyError` | такого ключа нет в словаре | `{}["a"]` |
| `AttributeError` | у объекта нет такого атрибута или метода | `"abc".push(1)` |
| `NameError` | используется неопределённое имя | `print(x)` (x не определён) |
| `FileNotFoundError` | файла нет | `open("нет.txt")` |
| `KeyboardInterrupt` | пользователь нажал Ctrl+C | работающая программа прервана |

Эти исключения образуют «семейное древо»: почти все — «потомки» `Exception`, `FileNotFoundError` — потомок `OSError` и т. д., поэтому `except OSError:` перехватит и `FileNotFoundError`, и `PermissionError`, и их родственников.

## 12.7 Не пишите `except`, который «ловит всё»

```python norun
try:
    result = calculate(data)
except:                     # опасно! ловит любые исключения, включая опечатки в именах и Ctrl+C
    print("что-то пошло не так")
```

При такой записи **настоящие ошибки молча проглатываются**: вы опечатались в имени переменной (`NameError`), а программа сообщает лишь «что-то пошло не так», и непонятно, где искать; если пользователь нажимает Ctrl+C, чтобы выйти, это тоже блокируется.

Принципы:

1. **перехватывайте только ожидаемые исключения, которые знаете, как обработать**, например `except ValueError:`;
2. если действительно нужна страховка (сервер не должен падать из-за одного неудачного запроса), пишите хотя бы `except Exception as e:` и **записывайте** ошибку в журнал, а не молча игнорируйте её;
3. никогда не пишите `except: pass`.

## 12.8 Исключения или `if`?

Оба стиля встречаются часто:

```python
d = {"a": 1}

# сначала проверить, потом действовать (Look Before You Leap)
if "b" in d:
    print(d["b"])
else:
    print("нет b")

# сначала действовать, ошибку обработать, если случится (Easier to Ask Forgiveness than Permission)
try:
    print(d["b"])
except KeyError:
    print("нет b")
```

Правило: **для ситуаций, которые легко проверить заранее и которые случаются часто, — `if`**; **для того, что заранее проверить трудно (не удалят ли файл перед самым открытием? не пропадёт ли сеть?) или что случается редко, — `try`**. Сообщество Python склоняется ко второму стилю, но ошибкой не является ни один.

## 12.9 `assert`: проверяем то, что «никогда не должно случиться»

`assert условие, "сообщение"` вызывает `AssertionError`, если условие ложно. Он проверяет **собственные предположения программы**, чтобы ловить ошибки:

```python
def average(nums):
    assert len(nums) > 0, "average() нужно хотя бы одно число"
    return sum(nums) / len(nums)

print(average([1, 2, 3]))
try:
    average([])
except AssertionError as e:
    print("AssertionError:", e)
```

> [!WARNING]
> `assert` нужен, чтобы ловить ошибки в программе, — **не** используйте его для проверки пользовательского ввода: при запуске Python с ключом `-O` все `assert` пропускаются. Ввод пользователя проверяйте через `if` + `raise ValueError(...)`. Чаще всего `assert` используется в **тестах** (pytest, урок 15).

## 12.10 Итоги

- Синтаксические ошибки не дают программе начаться; **исключения** возникают во время работы и останавливают её, если их не обработать.
- В `try:` — код, который может упасть, `except Тип:` обрабатывает ошибку; `as e` даёт объект исключения; `else` выполняется, если ошибок не было; `finally` выполняется всегда.
- Сообщайте об ошибках из своих функций через `raise ValueError("сообщение")`; наследуйтесь от `Exception`, чтобы определить свои исключения.
- Частые исключения: `ValueError`, `TypeError`, `ZeroDivisionError`, `IndexError`, `KeyError`, `FileNotFoundError`…
- Перехватывайте только ожидаемые исключения; не пишите голый `except:` и никогда — `except: pass`.
- Для легко проверяемого — `if`, для трудно проверяемого — `try`; `assert` проверяет предположения программы, а не ввод пользователя.

### Задание 4: Что выведет программа

```python
def f(x):
    try:
        print("start")
        return 10 / x
    except ZeroDivisionError:
        print("oops")
        return None
    finally:
        print("done")

print(f(2))
print(f(0))
```

<details>
<summary>Ответ и разбор</summary>

`f(2)`: печатает `start` и собирается вернуть 5.0, но сначала выполняется `finally` и печатает `done`; затем внешний `print` выводит `5.0`. `f(0)`: печатает `start`, деление на 0 переводит в `except`, который печатает `oops`, затем `finally` печатает `done`, и, наконец, внешний `print` выводит `None`.
</details>

### Задание 5: Почему не стоит писать `except:`?

- потому что он медленно работает

</details>

## 7.1 Зачем нужен контроль версий?

Наверняка вы видели такую папку:

```text
диплом.docx
диплом_правки.docx
диплом_правки2.docx
диплом_финал.docx
диплом_финал_точно_последний.docx
```

С кодом всё ещё хуже: поменяли одно — сломалось другое, а что именно меняли, уже не вспомнить; несколько человек работают над одним проектом и затирают изменения друг друга…

**Система контроля версий** решает эти проблемы. Это «машина времени», которая записывает каждое изменение: кто, когда, что и зачем изменил. Можно смотреть историю, сравнивать версии, вернуться к любой точке и работать вместе, не мешая друг другу.

**Git** — самая распространённая система контроля версий в мире; её создал в 2005 году Линус Торвальдс (автор Linux). **GitHub** — сайт, на котором хранят Git-репозитории (похожи на него GitLab, GitFlic и другие). Этот курс лежит на GitHub.

> [!NOTE]
> Коротко: **Git — инструмент** (программа на вашем компьютере), **GitHub — сайт** (место для хранения и публикации репозиториев).

## 7.2 Установка и настройка Git

| Система | Команда |
|---------|---------|
| Windows | `winget install -e --id Git.Git` (или скачайте с <https://git-scm.com/>; параметры по умолчанию подходят) |
| macOS | `xcode-select --install` уже включает git; или `brew install git` |
| Ubuntu/Debian | `sudo apt install git` |

Проверка:

```console
git --version
```

Перед первым использованием представьтесь Git (эти данные записываются в каждый коммит):

```console
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```

## 7.3 Главные понятия: репозиторий, индекс, коммит

```text
  рабочий каталог          индекс (staging)            репозиторий (история)
 (файлы, которые вы правите) ──git add──► (что пойдёт в коммит) ──git commit──► (цепочка «снимков»)
```

- **Репозиторий** (repo) — папка проекта под управлением Git. Внутри скрытая папка `.git` хранит всю историю.
- **Коммит** (commit) — **снимок** проекта в определённый момент с коротким сообщением.
- **Индекс** (staging area) — место, где вы выбираете, какие изменения войдут в следующий коммит; можно закоммитить только часть.

## 7.4 Практика: первый репозиторий

Повторяйте в терминале (по команде на строку):

```console
mkdir my-first-repo
cd my-first-repo
git init
```

`git init` превращает текущую папку в репозиторий Git. Теперь создайте в ней файл `hello.py`:

```python
print("версия один")
```

Посмотрите состояние:

```console
git status
```

Git сообщит об одном **неотслеживаемом** (untracked) файле `hello.py`. Добавьте его в индекс и закоммитьте:

```console
git add hello.py
git commit -m "Добавить hello.py"
```

Текст после `-m` — сообщение коммита. Хорошие сообщения **короткие и конкретные**: «Исправить деление на ноль», «Добавить страницу входа», а не «что-то поменял».

### Изменим ещё раз

Исправьте `hello.py`:

```python
print("версия два")
print("Я освоил Git!")
```

Посмотрите, что именно изменилось:

```console
git diff
```

Красные строки с `-` удалены, зелёные с `+` добавлены. Закоммитьте:

```console
git add hello.py
git commit -m "Обновить приветствие"
```

> [!TIP]
> `git add .` добавляет в индекс сразу все изменения в текущей папке (`.` — «эта папка»).

### Смотрим историю

```console
git log --oneline
```

```text
a1b2c3d (HEAD -> main) Обновить приветствие
9f8e7d6 Добавить hello.py
```

У каждого коммита есть уникальный идентификатор (хеш, например `a1b2c3d`). Посмотреть файл в старом коммите:

```console
git show 9f8e7d6:hello.py
```

Отменить незакоммиченные изменения и вернуть последнюю сохранённую версию:

```console
git restore hello.py
```

## 7.5 .gitignore: что не нужно записывать

Некоторым файлам не место в репозитории: скомпилированным программам, временным файлам, паролям и ключам. Создайте в корне репозитория текстовый файл `.gitignore` — по правилу на строку:

```text
# результаты сборки
*.exe
*.o
build/
# кэш Python
__pycache__/
# виртуальные окружения
.venv/
# секреты — никогда не коммитить!
.env
```

> [!WARNING]
> **Никогда не коммитьте пароли и API-ключи на GitHub.** Даже если потом удалить, они останутся в истории, а публичные репозитории сканируются автоматически. Если это случилось, немедленно отзовите ключ на сайте сервиса и создайте новый.

## 7.6 Ветки: параллельные вселенные

**Ветка** (branch) позволяет попробовать что-то новое, не трогая основную линию:

```text
main:      A ── B ── C ─────────── F (слияние)
                      \           /
feature:               D ── E ───
```

```console
git switch -c new-feature     # создать ветку new-feature и перейти в неё
# ...правки, add, commit...
git switch main               # вернуться в основную ветку
git merge new-feature         # влить изменения
```

Пока вы учитесь, вполне можно работать только в `main` — просто знайте, что ветки существуют.

## 7.7 GitHub: скачиваем этот курс

### Способ 1: ZIP-архив (Git не нужен)

Откройте <https://github.com/YeraldoSmith/Our-tutorial>, нажмите зелёную кнопку **Code** → **Download ZIP** и распакуйте. Минус: для обновления придётся скачивать заново.

### Способ 2: git clone (рекомендуется)

```console
git clone https://github.com/YeraldoSmith/Our-tutorial.git
cd Our-tutorial
```

`clone` скачивает весь репозиторий вместе с историей. Когда курс обновится, выполните в этой папке:

```console
git pull
```

Программа курса читает уроки из этой папки, поэтому тоже обновится.

## 7.8 GitHub: загружаем свой код

1. Зарегистрируйтесь: <https://github.com/signup>.
2. Нажмите **+** (справа вверху) → **New repository**, введите имя (например, `my-first-repo`) и нажмите **Create repository**.
3. По подсказкам на странице выполните в своём локальном репозитории:

   ```console
   git remote add origin https://github.com/ВАШ-ЛОГИН/my-first-repo.git
   git push -u origin main
   ```

4. При первой отправке потребуется войти. Пароль от аккаунта для push GitHub больше не принимает; установите **GitHub CLI** (`winget install -e --id GitHub.cli` или `brew install gh`) и выполните `gh auth login`, чтобы войти через браузер. В Windows вход через браузер предложит и Git Credential Manager, который устанавливается вместе с Git.

Дальше после каждого изменения: `git add .` → `git commit -m "сообщение"` → `git push`.

### Open source: форк и pull request

Хотите исправить опечатку в чужом проекте, например в этом курсе?

1. Нажмите **Fork** на странице проекта, чтобы скопировать его в свой аккаунт;
2. внесите и закоммитьте исправление в своей копии;
3. нажмите **Contribute → Open pull request**, чтобы предложить авторам влить его.

Это основной процесс работы в open source.

## 7.9 Шпаргалка

| Команда | Действие |
|---------|----------|
| `git init` | сделать текущую папку репозиторием |
| `git clone URL` | скачать удалённый репозиторий |
| `git status` | показать состояние (изменённые файлы) |
| `git add файл` / `git add .` | добавить изменения в индекс |
| `git commit -m "сообщение"` | закоммитить |
| `git log --oneline` | показать историю |
| `git diff` | показать изменения вне индекса |
| `git restore файл` | отменить изменения в рабочем каталоге |
| `git switch -c имя` | создать ветку и перейти в неё |
| `git pull` | получить и влить свежие изменения |
| `git push` | отправить локальные коммиты |

## 7.10 Итоги

- Контроль версий — машина времени: записывает каждое изменение, позволяет смотреть, сравнивать, откатывать и работать вместе.
- **Git** — инструмент, **GitHub** — сайт для хранения репозиториев.
- Основной цикл: правка → `git add` → `git commit -m "..."`; смотрим через `git status`, `git diff`, `git log`.
- `.gitignore` исключает файлы; **никогда не коммитьте пароли и ключи**.
- `git clone` — скачать, `git pull` — обновить, `git push` — отправить.

# 6. Как компьютер хранит числа и текст

> 🎯 **Цели урока**: понять двоичную систему, биты и байты; переводить числа между десятичной, двоичной и шестнадцатеричной системами; узнать, почему `0.1 + 0.2` не равно `0.3`; разобраться, как ASCII, Unicode и UTF-8 позволяют компьютеру показывать текст.
>
> ⏱ **Время**: 40 минут　|　📋 **Что нужно знать**: урок 1

Урок немного теоретический, но он объясняет многие странности, которые встретятся позже: почему у чисел есть предел, почему дроби считаются неточно и почему текст иногда превращается в «кракозябры».

## 6.1 Всё — это нули и единицы

Внутри компьютера — миллиарды крошечных электронных переключателей (транзисторов). У каждого всего два состояния: **выключен (0)** и **включён (1)**. Поэтому всё в компьютере — числа, текст, картинки, звук, программы — в конечном счёте записано нулями и единицами.

- Один 0 или 1 называется **битом** — это наименьшая единица информации.
- **8 бит** составляют **байт** — основную единицу хранения.

```text
1 байт = 8 бит:  0 1 0 0 0 0 0 1
1 КБ ≈ 1000 байт      (страница простого текста)
1 МБ ≈ 1000 КБ        (сжатая песня)
1 ГБ ≈ 1000 МБ        (фильм)
1 ТБ ≈ 1000 ГБ        (жёсткий диск)
```

> [!NOTE]
> Компьютеры часто считают по 1024, а не по 1000 (1 КиБ = 1024 байта). Поэтому купленный диск на «1 ТБ» в системе показывается примерно как 931 ГБ — стороны используют разные единицы.

## 6.2 Двоичная система: считаем только нулями и единицами

Обычно мы пользуемся **десятичной** системой: десять цифр 0–9, при достижении десяти — перенос в следующий разряд. Разряды означают 1, 10, 100:

```text
десятичное 345 = 3×100 + 4×10 + 5×1
```

В **двоичной** системе только 0 и 1, а перенос происходит на двойке. Разряды означают 1, 2, 4, 8, 16… (степени двойки):

```text
двоичное 1101 = 1×8 + 1×4 + 0×2 + 1×1 = 13 (десятичное)

веса разрядов:  8   4   2   1
двоичное:       1   1   0   1
```

Счёт от 0 до 8:

| Десятичное | Двоичное |
|------------|----------|
| 0 | 0 |
| 1 | 1 |
| 2 | 10 |
| 3 | 11 |
| 4 | 100 |
| 5 | 101 |
| 6 | 110 |
| 7 | 111 |
| 8 | 1000 |

### Из десятичной в двоичную: делим на 2

Переведём 13: делим на 2 снова и снова, записываем остатки и читаем их **снизу вверх**:

```text
13 ÷ 2 = 6, остаток 1   ↑
 6 ÷ 2 = 3, остаток 0   │
 3 ÷ 2 = 1, остаток 1   │ снизу вверх: 1101
 1 ÷ 2 = 0, остаток 1   │
```

Проверим на Python:

```python
print(bin(13))          # десятичное → двоичное; 0b значит «это двоичное число»
print(int("1101", 2))   # двоичная запись → десятичное
print(0b1101)           # двоичное число прямо в коде
```

## 6.3 Шестнадцатеричная система: сокращение для двоичной

Двоичная запись длинная и неудобна для людей. В **шестнадцатеричной** системе 16 цифр: 0–9 и A–F (A=10, B=11 … F=15). **Одна шестнадцатеричная цифра — это ровно четыре двоичные**, поэтому её удобно использовать как сокращение:

```text
двоичное 1111 1111  →  шестн. F F  →  десятичное 255
двоичное 0100 0001  →  шестн. 4 1  →  десятичное 65
```

Шестнадцатеричные числа встречаются повсюду: коды цветов `#FF8800` (красный FF, зелёный 88, синий 00), адреса памяти `0x7ffd5a3c`, коды символов `U+044F`.

```python
print(hex(255))         # 0xff
print(0xFF)             # 255
print(int("ff", 16))    # 255
```

## 6.4 Насколько большим может быть целое число?

Компьютер хранит целое число в **фиксированном количестве бит**, и это ограничивает диапазон:

| Бит | Без знака (только ≥ 0) | Со знаком (может быть отрицательным) |
|-----|------------------------|--------------------------------------|
| 8 | 0 … 255 | −128 … 127 |
| 16 | 0 … 65 535 | −32 768 … 32 767 |
| 32 | 0 … около 4,29 млрд | около −2,15 … 2,15 млрд |
| 64 | 0 … около 1,8×10¹⁹ | около ±9,2×10¹⁸ |

n бит дают 2ⁿ разных значений: 8 бит — 2⁸ = 256 значений, отсюда 0–255.

Если результат не помещается, происходит **переполнение** (overflow) — как у старого автомобильного счётчика пробега, который после 999999 показывает 000000. В C, C++, Java, Rust и Go целые числа имеют фиксированный размер — следите за переполнением; в Python целые просто растут, и переполнения не бывает:

```python
print(2 ** 100)    # Python вычисляет точный результат
```

> [!NOTE]
> Отрицательные числа обычно хранятся в так называемом **дополнительном коде** (two's complement). Сейчас вникать не нужно — это объясняется в курсах C и ассемблера.

## 6.5 Дроби: почему 0.1 + 0.2 — не 0.3?

Попробуйте:

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

Вывод:

```text
0.30000000000000004
False
```

Это не ошибка Python — так ведут себя почти все языки. Компьютер хранит дроби в двоичном виде (**числа с плавающей точкой**, floating-point), а 0.1 в двоичной системе — **бесконечная периодическая дробь**, как 1/3 = 0,3333… в десятичной. Компьютер хранит очень близкое приближение, и при сложении приближений появляется крошечная погрешность.

Что делать:

- При выводе **округляйте**: `round(0.1 + 0.2, 2)` даёт `0.3`.
- Сравнивая дроби, проверяйте, что они **достаточно близки**, а не точно равны: `abs(a - b) < 1e-9`.
- **Не используйте float для денег**: храните копейки целым числом (1999 копеек = 19,99 ₽) или используйте десятичный тип (модуль `decimal` в Python).

```python
print(round(0.1 + 0.2, 2))
print(abs((0.1 + 0.2) - 0.3) < 1e-9)
```

## 6.6 Текст: у каждого символа есть номер

Компьютер хранит текст так: **каждому символу присваивается номер**, и сохраняются номера.

### ASCII: первый стандарт

**ASCII** (1960-е годы) пронумеровал 128 символов: английские буквы, цифры, знаки препинания и управляющие символы:

| Символ | Код (десятичный) | Код (шестн.) |
|--------|------------------|--------------|
| `A` | 65 | 41 |
| `B` | 66 | 42 |
| `a` | 97 | 61 |
| `0` | 48 | 30 |
| пробел | 32 | 20 |

Внимание: у символа `'0'` код 48, **а не** 0. «Число 0» и «текст 0» для компьютера — разные вещи.

```python
print(ord("A"))     # символ → код
print(chr(66))      # код → символ
print(ord("0"))
```

### Unicode: все письменности мира

В ASCII есть только английский алфавит. Чтобы записывать кириллицу, китайский, арабский, эмодзи и всё остальное, создали **Unicode** — уникальный номер, **кодовую точку** (code point), практически для каждого символа в мире; записывается как `U+` и шестнадцатеричное число. В Unicode больше 150 000 символов:

```text
A   → U+0041
я   → U+044F
中  → U+4E2D
😀  → U+1F600
```

```python
print(ord("я"))            # 1103
print(hex(ord("я")))       # 0x44f
print(chr(0x1F600))        # 😀
```

### UTF-8: как хранить кодовые точки в байтах

Кодовая точка — число; чтобы записать его в файл, нужно решить, сколько байт использовать и в каком порядке, — это **кодировка**. Самая распространённая — **UTF-8**:

- символы ASCII, например латинские буквы: **1 байт** (полная совместимость с ASCII);
- кириллица, греческий и т. п.: **2 байта**;
- большинство китайских, японских и корейских иероглифов: **3 байта**;
- эмодзи и некоторые редкие символы: **4 байта**.

```python
print("A".encode("utf-8"))           # b'A'          → 1 байт
print("я".encode("utf-8"))           # b'\xd1\x8f'   → 2 байта
print(len("привет"))                  # 6 символов
print(len("привет".encode("utf-8")))  # 12 байт
```

### Откуда берутся «кракозябры»?

Если файл, сохранённый в UTF-8, прочитать как файл в другой кодировке (например, старой Windows-1251), байты истолковываются неправильно, и вместо «привет» появляется что-то вроде `РїСЂРёРІРµС‚`. Лекарство простое: **везде используйте UTF-8**.

## 6.7 Итоги

- Всё в компьютере — нули и единицы; один бит — 0 или 1, **8 бит = 1 байт**.
- **Двоичная** система переносит на двойке, веса разрядов 1, 2, 4, 8…; **шестнадцатеричная** использует 0–9 и A–F, одна цифра = четыре бита.
- Python: `bin()`, `hex()`, `int("…", 2)`, `int("…", 16)`.
- Целые числа имеют фиксированный размер и диапазон; выход за него — **переполнение** (кроме Python).
- У чисел с плавающей точкой есть крошечные погрешности: округляйте при выводе, сравнивайте «с допуском», для денег используйте целые или `decimal`.
- У символов есть номера: ASCII (английский) → **Unicode** (всё); **UTF-8** хранит кодовую точку в 1–4 байтах. Используйте UTF-8 везде — и текст не испортится.

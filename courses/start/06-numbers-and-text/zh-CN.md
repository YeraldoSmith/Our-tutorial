# 6. 电脑如何存储数字和文字

> 🎯 **本课目标**：理解二进制、位和字节；会在十进制、二进制、十六进制之间转换；知道为什么 `0.1 + 0.2` 不等于 `0.3`；明白 ASCII、Unicode 和 UTF-8 是怎么让电脑显示文字的。
>
> ⏱ **预计用时**：40 分钟　｜　📋 **前置知识**：第 1 课

这一课有一点「理论」，但它能解释很多以后会遇到的怪现象：为什么数字有大小上限、为什么小数算不准、为什么文字会变成乱码。

## 6.1 一切都是 0 和 1

电脑内部是由几十亿个微小的电子开关（晶体管）组成的。每个开关只有两种状态：**关（0）** 和 **开（1）**。所以电脑里的所有东西——数字、文字、图片、声音、程序——最终都用 0 和 1 来表示。

- 一个 0 或 1 叫一个**位**（bit，比特），是最小的信息单位。
- **8 个位**组成一个**字节**（byte），这是存储的基本单位。

```text
1 字节 = 8 位:  0 1 0 0 0 0 0 1
1 KB ≈ 1000 字节      （一页纯文字）
1 MB ≈ 1000 KB        （一首压缩的歌）
1 GB ≈ 1000 MB        （一部电影）
1 TB ≈ 1000 GB        （一块硬盘）
```

> [!NOTE]
> 严格来说，计算机里经常用 1024 而不是 1000 作为换算单位（1 KiB = 1024 字节）。这就是为什么买来的「1 TB」硬盘在电脑里显示只有约 931 GB——两边用的换算方式不同。

## 6.2 二进制：只用 0 和 1 计数

我们平时用的是**十进制**：每一位有 0～9 十个数字，满十进一。个位、十位、百位分别代表 1、10、100：

```text
十进制 345 = 3×100 + 4×10 + 5×1
```

**二进制**只有 0 和 1 两个数字，满二进一。每一位代表的是 1、2、4、8、16……（2 的次方）：

```text
二进制 1101 = 1×8 + 1×4 + 0×2 + 1×1 = 13（十进制）

位的权重:   8   4   2   1
二进制:     1   1   0   1
```

从 0 数到 8 是这样的：

| 十进制 | 二进制 |
|--------|--------|
| 0 | 0 |
| 1 | 1 |
| 2 | 10 |
| 3 | 11 |
| 4 | 100 |
| 5 | 101 |
| 6 | 110 |
| 7 | 111 |
| 8 | 1000 |

### 十进制转二进制：不断除以 2

把 13 转成二进制：不停地除以 2，记下余数，最后**从下往上**读余数：

```text
13 ÷ 2 = 6 …… 1   ↑
 6 ÷ 2 = 3 …… 0   │
 3 ÷ 2 = 1 …… 1   │ 从下往上读：1101
 1 ÷ 2 = 0 …… 1   │
```

用 Python 验证一下：

```python
print(bin(13))          # 十进制 → 二进制，0b 开头表示「这是二进制」
print(int("1101", 2))   # 二进制文字 → 十进制
print(0b1101)           # 直接写二进制数
```

## 6.3 十六进制：二进制的「简写」

二进制太长了，不方便人看。**十六进制**每一位有 16 种取值：0～9 和 A～F（A=10，B=11……F=15）。**一位十六进制正好对应四位二进制**，所以它常用来简写二进制：

```text
二进制    1111 1111  →  十六进制  F F   →  十进制 255
二进制    0100 0001  →  十六进制  4 1   →  十进制 65
```

你会在很多地方见到十六进制：颜色代码 `#FF8800`（红 FF、绿 88、蓝 00）、内存地址 `0x7ffd5a3c`、文字编码 `U+4E2D`。

```python
print(hex(255))         # 0xff
print(0xFF)             # 255
print(int("ff", 16))    # 255
```

## 6.4 整数的范围

电脑用**固定数量的位**来存一个整数。位数决定了能存的范围：

| 位数 | 无符号（只有 ≥0） | 有符号（可以为负） |
|------|-------------------|--------------------|
| 8 位 | 0 ～ 255 | −128 ～ 127 |
| 16 位 | 0 ～ 65 535 | −32 768 ～ 32 767 |
| 32 位 | 0 ～ 约 42.9 亿 | 约 −21.4 亿 ～ 21.4 亿 |
| 64 位 | 0 ～ 约 1.8×10¹⁹ | 约 ±9.2×10¹⁸ |

n 位最多能表示 2ⁿ 个不同的值。比如 8 位：2⁸ = 256 个值，所以是 0～255。

如果计算结果超出了范围，就会发生**溢出**（overflow）：就像汽车里程表到了 999999 再走一公里会变回 000000。C、C++、Java、Rust、Go 的整数都有固定大小，要注意溢出；Python 的整数会自动变大，没有这个问题：

```python
print(2 ** 100)    # Python 能算出完整的结果
```

> [!NOTE]
> 负数在电脑里一般用一种叫**补码**（two's complement）的方式表示。现在不用深究，学 C 语言和汇编时会详细讲。

## 6.5 小数：为什么 0.1 + 0.2 ≠ 0.3？

试试这个：

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

输出：

```text
0.30000000000000004
False
```

这不是 Python 的 bug，几乎所有编程语言都一样。原因是：电脑用二进制存小数（叫**浮点数**，floating-point），而 0.1 在二进制里是一个**无限循环小数**——就像 1/3 在十进制里是 0.3333…… 一样写不完。电脑只能存一个非常接近的近似值，几个近似值加起来，就出现了极小的误差。

怎么办？

- 显示结果时**四舍五入**：`round(0.1 + 0.2, 2)` 得到 `0.3`。
- 比较两个小数时，看它们**是否足够接近**，而不是是否完全相等：`abs(a - b) < 1e-9`。
- **涉及金钱时不要用浮点数**：用整数表示「分」（例如 1999 分 = 19.99 元），或者使用专门的十进制类型（Python 的 `decimal` 模块）。

```python
print(round(0.1 + 0.2, 2))
print(abs((0.1 + 0.2) - 0.3) < 1e-9)
```

## 6.6 文字：每个字符都有一个编号

电脑里存文字的方法是：**给每个字符分配一个数字编号**，存的其实是编号。

### ASCII：最早的标准

1960 年代制定的 **ASCII** 码给 128 个字符编了号：英文字母、数字、标点和一些控制字符。例如：

| 字符 | 编号（十进制） | 编号（十六进制） |
|------|----------------|------------------|
| `A` | 65 | 41 |
| `B` | 66 | 42 |
| `a` | 97 | 61 |
| `0` | 48 | 30 |
| 空格 | 32 | 20 |

注意：字符 `'0'` 的编号是 48，**不是** 0。「数字 0」和「文字 0」在电脑里是两回事。

```python
print(ord("A"))     # 字符 → 编号
print(chr(66))      # 编号 → 字符
print(ord("0"))
```

### Unicode：全世界的文字

ASCII 只有英文。为了表示中文、日文、阿拉伯文、emoji……人们制定了 **Unicode**（统一码）：给世界上几乎所有文字的每个字符一个唯一编号，叫**码点**（code point），写成 `U+` 加十六进制，目前已经收录了 15 万个以上的字符：

```text
A   → U+0041
中  → U+4E2D
я   → U+044F
😀  → U+1F600
```

```python
print(ord("中"))           # 20013
print(hex(ord("中")))      # 0x4e2d
print(chr(0x1F600))        # 😀
```

### UTF-8：把编号存成字节

码点是数字，存进文件时还要决定「用几个字节、怎么排列」，这叫**编码**（encoding）。**UTF-8** 是现在最通用的编码：

- 英文字母等 ASCII 字符：**1 个字节**（和 ASCII 完全兼容）；
- 俄文、希腊文等：**2 个字节**；
- 中文、日文、韩文的大部分字：**3 个字节**；
- emoji 和一些罕见字：**4 个字节**。

```python
print("A".encode("utf-8"))      # b'A'          → 1 个字节
print("中".encode("utf-8"))     # b'\xe4\xb8\xad' → 3 个字节
print(len("中文"))               # 2：两个字符
print(len("中文".encode("utf-8")))  # 6：六个字节
```

### 乱码是怎么来的？

如果一个文件用 UTF-8 保存，却被当成另一种编码（例如中文 Windows 老程序常用的 GBK）来读，字节就会被错误地解释，出现「锟斤拷」「浣犲ソ」这样的**乱码**。解决办法很简单：**所有地方统一使用 UTF-8**。

## 6.7 小结

- 电脑里一切都是 0 和 1；1 位是一个 0/1，**8 位 = 1 字节**。
- **二进制**逢二进一，每位权重 1、2、4、8……；**十六进制**用 0～9、A～F，一位对应四位二进制。
- Python：`bin()`、`hex()`、`int("…", 2)`、`int("…", 16)`。
- 整数用固定位数存储，有范围，超出会**溢出**（Python 除外）。
- 浮点数有微小误差：显示时四舍五入，比较时看「足够接近」，金钱用整数或 `decimal`。
- 每个字符有编号：ASCII（英文）→ **Unicode**（全世界）；**UTF-8** 把编号存成 1～4 个字节。统一用 UTF-8 就不会乱码。

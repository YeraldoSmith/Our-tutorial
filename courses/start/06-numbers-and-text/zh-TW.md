# 6. 電腦如何儲存數字和文字

> 🎯 **本課目標**：理解二進位制、位和位元組；會在十進位制、二進位制、十六進位制之間轉換；知道為什麼 `0.1 + 0.2` 不等於 `0.3`；明白 ASCII、Unicode 和 UTF-8 是怎麼讓電腦顯示文字的。
>
> ⏱ **預計用時**：40 分鐘　｜　📋 **前置知識**：第 1 課

這一課有一點「理論」，但它能解釋很多以後會遇到的怪現象：為什麼數字有大小上限、為什麼小數算不準、為什麼文字會變成亂碼。

## 6.1 一切都是 0 和 1

電腦內部是由幾十億個微小的電子開關（電晶體）組成的。每個開關只有兩種狀態：**關（0）** 和 **開（1）**。所以電腦裡的所有東西——數字、文字、圖片、聲音、程式——最終都用 0 和 1 來表示。

- 一個 0 或 1 叫一個**位**（bit，位元），是最小的資訊單位。
- **8 個位**組成一個**位元組**（byte），這是儲存的基本單位。

```text
1 位元組 = 8 位:  0 1 0 0 0 0 0 1
1 KB ≈ 1000 位元組      （一頁純文字）
1 MB ≈ 1000 KB        （一首壓縮的歌）
1 GB ≈ 1000 MB        （一部電影）
1 TB ≈ 1000 GB        （一塊硬碟）
```

> [!NOTE]
> 嚴格來說，計算機裡經常用 1024 而不是 1000 作為換算單位（1 KiB = 1024 位元組）。這就是為什麼買來的「1 TB」硬碟在電腦裡顯示只有約 931 GB——兩邊用的換算方式不同。

## 6.2 二進位制：只用 0 和 1 計數

我們平時用的是**十進位制**：每一位有 0～9 十個數字，滿十進一。個位、十位、百位分別代表 1、10、100：

```text
十進位制 345 = 3×100 + 4×10 + 5×1
```

**二進位制**只有 0 和 1 兩個數字，滿二進一。每一位代表的是 1、2、4、8、16……（2 的次方）：

```text
二進位制 1101 = 1×8 + 1×4 + 0×2 + 1×1 = 13（十進位制）

位的權重:   8   4   2   1
二進位制:     1   1   0   1
```

從 0 數到 8 是這樣的：

| 十進位制 | 二進位制 |
|--------|--------|
| 0 | 0 |
| 1 | 1 |
| 2 | 10 |
| 3 | 11 |
| 4 | 100 |
| 5 | 101 |
| 6 | 110 |
| 7 | 111 |
| 8 | 1000 |

### 十進位制轉二進位制：不斷除以 2

把 13 轉成二進位制：不停地除以 2，記下餘數，最後**從下往上**讀餘數：

```text
13 ÷ 2 = 6 …… 1   ↑
 6 ÷ 2 = 3 …… 0   │
 3 ÷ 2 = 1 …… 1   │ 從下往上讀：1101
 1 ÷ 2 = 0 …… 1   │
```

用 Python 驗證一下：

```python
print(bin(13))          # 十進位制 → 二進位制，0b 開頭表示「這是二進位制」
print(int("1101", 2))   # 二進位制文字 → 十進位制
print(0b1101)           # 直接寫二進位制數
```

## 6.3 十六進位制：二進位制的「簡寫」

二進位制太長了，不方便人看。**十六進位制**每一位有 16 種取值：0～9 和 A～F（A=10，B=11……F=15）。**一位十六進位制正好對應四位二進位制**，所以它常用來簡寫二進位制：

```text
二進位制    1111 1111  →  十六進位制  F F   →  十進位制 255
二進位制    0100 0001  →  十六進位制  4 1   →  十進位制 65
```

你會在很多地方見到十六進位制：顏色程式碼 `#FF8800`（紅 FF、綠 88、藍 00）、記憶體地址 `0x7ffd5a3c`、文字編碼 `U+4E2D`。

```python
print(hex(255))         # 0xff
print(0xFF)             # 255
print(int("ff", 16))    # 255
```

## 6.4 整數的範圍

電腦用**固定數量的位**來存一個整數。位數決定了能存的範圍：

| 位數 | 無符號（只有 ≥0） | 有符號（可以為負） |
|------|-------------------|--------------------|
| 8 位 | 0 ～ 255 | −128 ～ 127 |
| 16 位 | 0 ～ 65 535 | −32 768 ～ 32 767 |
| 32 位 | 0 ～ 約 42.9 億 | 約 −21.4 億 ～ 21.4 億 |
| 64 位 | 0 ～ 約 1.8×10¹⁹ | 約 ±9.2×10¹⁸ |

n 位最多能表示 2ⁿ 個不同的值。比如 8 位：2⁸ = 256 個值，所以是 0～255。

如果計算結果超出了範圍，就會發生**溢位**（overflow）：就像汽車里程錶到了 999999 再走一公里會變回 000000。C、C++、Java、Rust、Go 的整數都有固定大小，要注意溢位；Python 的整數會自動變大，沒有這個問題：

```python
print(2 ** 100)    # Python 能算出完整的結果
```

> [!NOTE]
> 負數在電腦裡一般用一種叫**補碼**（two's complement）的方式表示。現在不用深究，學 C 語言和彙編時會詳細講。

## 6.5 小數：為什麼 0.1 + 0.2 ≠ 0.3？

試試這個：

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

輸出：

```text
0.30000000000000004
False
```

這不是 Python 的 bug，幾乎所有程式語言都一樣。原因是：電腦用二進位制存小數（叫**浮點數**，floating-point），而 0.1 在二進位制裡是一個**無限迴圈小數**——就像 1/3 在十進位制裡是 0.3333…… 一樣寫不完。電腦只能存一個非常接近的近似值，幾個近似值加起來，就出現了極小的誤差。

怎麼辦？

- 顯示結果時**四捨五入**：`round(0.1 + 0.2, 2)` 得到 `0.3`。
- 比較兩個小數時，看它們**是否足夠接近**，而不是是否完全相等：`abs(a - b) < 1e-9`。
- **涉及金錢時不要用浮點數**：用整數表示「分」（例如 1999 分 = 19.99 元），或者使用專門的十進位制型別（Python 的 `decimal` 模組）。

```python
print(round(0.1 + 0.2, 2))
print(abs((0.1 + 0.2) - 0.3) < 1e-9)
```

## 6.6 文字：每個字元都有一個編號

電腦裡存文字的方法是：**給每個字元分配一個數字編號**，存的其實是編號。

### ASCII：最早的標準

1960 年代制定的 **ASCII** 碼給 128 個字元編了號：英文字母、數字、標點和一些控制字元。例如：

| 字元 | 編號（十進位制） | 編號（十六進位制） |
|------|----------------|------------------|
| `A` | 65 | 41 |
| `B` | 66 | 42 |
| `a` | 97 | 61 |
| `0` | 48 | 30 |
| 空格 | 32 | 20 |

注意：字元 `'0'` 的編號是 48，**不是** 0。「數字 0」和「文字 0」在電腦裡是兩回事。

```python
print(ord("A"))     # 字元 → 編號
print(chr(66))      # 編號 → 字元
print(ord("0"))
```

### Unicode：全世界的文字

ASCII 只有英文。為了表示中文、日文、阿拉伯文、emoji……人們制定了 **Unicode**（統一碼）：給世界上幾乎所有文字的每個字元一個唯一編號，叫**碼點**（code point），寫成 `U+` 加十六進位制，目前已經收錄了 15 萬個以上的字元：

```text
A   → U+0041
中  → U+4E2D
я   → U+044F
😀  → U+1F600
```

```python
print(ord("中"))           # 20013
print(hex(ord("中")))      # 0x4e2d
print(chr(0x1F600))        # 😀
```

### UTF-8：把編號存成位元組

碼點是數字，存進檔案時還要決定「用幾個位元組、怎麼排列」，這叫**編碼**（encoding）。**UTF-8** 是現在最通用的編碼：

- 英文字母等 ASCII 字元：**1 個位元組**（和 ASCII 完全相容）；
- 俄文、希臘文等：**2 個位元組**；
- 中文、日文、韓文的大部分字：**3 個位元組**；
- emoji 和一些罕見字：**4 個位元組**。

```python
print("A".encode("utf-8"))      # b'A'          → 1 個位元組
print("中".encode("utf-8"))     # b'\xe4\xb8\xad' → 3 個位元組
print(len("中文"))               # 2：兩個字元
print(len("中文".encode("utf-8")))  # 6：六個位元組
```

### 亂碼是怎麼來的？

如果一個檔案用 UTF-8 儲存，卻被當成另一種編碼（例如中文 Windows 老程式常用的 GBK）來讀，位元組就會被錯誤地解釋，出現「錕斤拷」「浣犲ソ」這樣的**亂碼**。解決辦法很簡單：**所有地方統一使用 UTF-8**。

## 6.7 小結

- 電腦裡一切都是 0 和 1；1 位是一個 0/1，**8 位 = 1 位元組**。
- **二進位制**逢二進一，每位權重 1、2、4、8……；**十六進位制**用 0～9、A～F，一位對應四位二進位制。
- Python：`bin()`、`hex()`、`int("…", 2)`、`int("…", 16)`。
- 整數用固定位數儲存，有範圍，超出會**溢位**（Python 除外）。
- 浮點數有微小誤差：顯示時四捨五入，比較時看「足夠接近」，金錢用整數或 `decimal`。
- 每個字元有編號：ASCII（英文）→ **Unicode**（全世界）；**UTF-8** 把編號存成 1～4 個位元組。統一用 UTF-8 就不會亂碼。

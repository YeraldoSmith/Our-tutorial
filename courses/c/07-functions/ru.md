## 7.1 Определение и вызов функций

Мы всё время пользовались функциями, написанными другими, — `printf`, `scanf`, `sqrt`… да и `main` тоже функция. Теперь напишем свои:

```c
#include <stdio.h>

int square(int x) {          // тип_результата  имя(тип_параметра имя_параметра)
    return x * x;            // return: вернуть результат вызывающему и завершить функцию
}

void greet(void) {           // void: ничего не возвращает; void в параметрах: аргументов нет
    printf("Привет!\n");
}

int main(void) {
    greet();
    int a = square(5);       // вызываем square, передавая 5 в x, получаем 25
    printf("%d\n", a);
    printf("%d\n", square(3) + square(4));   // возвращаемые значения можно сразу использовать: 25
    return 0;
}
```

| Часть | Смысл |
|-------|-------|
| `int` | **тип результата**: функция возвращает `int`. Если она ничего не возвращает, пишут `void` |
| `square` | имя функции; правила именования — как у переменных |
| `(int x)` | **список параметров**: у каждого параметра есть тип; несколько параметров разделяются запятыми, например `(int a, double b)` |
| `return x * x;` | вернуть результат. Функция `void` может досрочно завершиться пустым `return;` или обойтись без него |

Как и в Python, функции избавляют от повторов и делают программы понятнее и проще для проверки. В отличие от Python, **у параметров и результата обязательно указываются типы**.

## 7.2 Сначала объявить, потом использовать: прототипы функций

Компилятор C читает код **сверху вниз**. Если `main` вызывает функцию, написанную после `main`, то при чтении вызова компилятор её ещё не знает:

```c norun
#include <stdio.h>

int main(void) {
    printf("%d\n", square(4));     // здесь square ещё неизвестна
    return 0;
}

int square(int x) {
    return x * x;
}
```

```text
warning: implicit declaration of function 'square' [-Wimplicit-function-declaration]
```

(Новые компиляторы сообщают об ошибке.) Исправить можно двумя способами: перенести определение выше вызова или раньше написать **прототип функции** (объявление) — только «подпись», без тела, с точкой с запятой в конце:

```c
#include <stdio.h>

int square(int x);                 // прототип: сообщаем компилятору «такая функция есть»
double average(int a, int b);

int main(void) {
    printf("%d %.1f\n", square(4), average(3, 4));
    return 0;
}

int square(int x) {                // определения могут идти потом
    return x * x;
}

double average(int a, int b) {
    return (a + b) / 2.0;          // деление на 2.0 — дробное деление (урок 3)
}
```

Многие программы на C устроены так: сначала прототипы всех функций, затем `main`, затем определения функций. В программах из нескольких файлов прототипы выносят в **заголовочные файлы** (`.h`) — `#include <stdio.h>` на самом деле подключает прототипы `printf` и других функций. Об этом — в уроке 14.

## 7.3 Передача по значению: функция получает копии

При вызове функции **значения аргументов копируются** в параметры. Изменение параметра внутри функции не влияет на переменную снаружи:

```c
#include <stdio.h>

void try_to_change(int n) {
    n = 100;                       // меняется только копия
    printf("внутри функции n = %d\n", n);
}

void swap(int a, int b) {          // пытаемся поменять два числа местами…
    int t = a;
    a = b;
    b = t;
}

int main(void) {
    int x = 5;
    try_to_change(x);
    printf("снаружи x = %d\n", x); // всё ещё 5

    int p = 1, q = 2;
    swap(p, q);
    printf("p = %d, q = %d\n", p, q);   // всё ещё 1 и 2: обмен не удался!
    return 0;
}
```

Чтобы функция могла менять переменные снаружи (настоящий `swap`) или «возвращать несколько значений», ей передают **адреса** переменных — именно поэтому в `scanf("%d", &x)` нужен `&`. Изучив указатели в уроке 10, мы напишем работающий `swap`.

## 7.4 Локальные, глобальные и статические переменные

```c
#include <stdio.h>

int total_calls = 0;               // глобальная переменная: вне всех функций, доступна им всем

int next_id(void) {
    static int id = 0;             // статическая локальная переменная: инициализируется один раз и сохраняет значение после выхода из функции
    id++;
    total_calls++;
    return id;
}

int main(void) {
    int a = next_id();
    int b = next_id();
    int c = next_id();
    printf("%d %d %d\n", a, b, c);          // 1 2 3
    printf("всего вызовов: %d\n", total_calls);
    return 0;
}
```

| Вид | Где записана | Кому доступна | Сколько живёт |
|-----|--------------|---------------|---------------|
| локальная переменная | внутри функции (или блока) | только этой функции | до конца функции |
| `static` локальная | внутри функции, со словом `static` | только этой функции | всё время работы программы, значение сохраняется |
| глобальная переменная | вне всех функций | всем функциям | всё время работы программы |

> [!TIP]
> **Пользуйтесь глобальными переменными как можно реже.** Их может изменить любая функция, и в большой программе очень трудно понять, кто и когда что поменял. Всё, что можно передать через параметры и возвращаемые значения, передавайте так.

## 7.5 Рекурсия: функция вызывает сама себя

Как и в Python (урок 10 курса Python), функции в C могут вызывать сами себя:

```c
#include <stdio.h>

long long factorial(int n) {
    if (n <= 1) {                  // условие остановки
        return 1;
    }
    return n * factorial(n - 1);   // сводим задачу к меньшей задаче того же вида
}

int main(void) {
    for (int i = 0; i <= 20; i += 5) {
        printf("%d! = %lld\n", i, factorial(i));
    }
    return 0;
}
```

Один из самых красивых примеров рекурсии — **Ханойская башня**: перенести n дисков со стержня A на стержень C по одному, никогда не кладя больший диск на меньший. Идея: перенести верхние n−1 дисков на B, перенести самый большой на C, затем перенести n−1 дисков с B на C — а «перенести n−1 дисков» — это та же задача:

```c
#include <stdio.h>

void hanoi(int n, char from, char via, char to) {
    if (n == 0) {
        return;
    }
    hanoi(n - 1, from, to, via);         // верхние n-1: from → via
    printf("%c -> %c\n", from, to);      // самый большой: from → to
    hanoi(n - 1, via, from, to);         // те n-1: via → to
}

int main(void) {
    hanoi(3, 'A', 'B', 'C');             // для 3 дисков нужно 7 ходов
    return 0;
}
```

### Стек вызовов

При каждом вызове функции компьютер выделяет в памяти на **стеке** (stack) кусочек для параметров этого вызова, его локальных переменных и «куда вернуться по завершении»; при возврате из функции этот кусочек освобождается. Пока выполняется рекурсия `factorial(4)`, на стеке одновременно лежат четыре слоя: `factorial(4)`, `factorial(3)`, `factorial(2)` и `factorial(1)`.

Размер стека ограничен (обычно несколько МБ). Если рекурсивная функция **забыла условие остановки** или уходит слишком глубоко, стек заканчивается — **переполнение стека** (stack overflow), — и программа падает, обычно с сообщением `Segmentation fault`. Знаменитый сайт вопросов и ответов для программистов Stack Overflow назван именно в честь этого.

## 7.6 Привычки хороших функций

- **Одна функция — одна задача**, и имя говорит, что она делает: `is_prime`, `read_scores`, `print_report`;
- функции должны быть короткими; если функция не помещается на экран, подумайте, как её разделить;
- получайте данные через параметры и отдавайте результат через возвращаемое значение, поменьше полагайтесь на глобальные переменные;
- разделяйте «вычисления» и «ввод-вывод»: `int max3(int a, int b, int c)` только вычисляет, а печать оставляет `main` — такие функции легче всего проверять и переиспользовать.

## 7.7 Итоги

- Определение функции: `тип_результата имя(тип параметр, ...) { ... return значение; }`; если ничего не возвращается — `void`, если нет параметров — `(void)`.
- C читает сверху вниз: функции нужно **объявлять до использования**, например прототипом `int square(int x);` выше по тексту.
- Аргументы **передаются по значению**: изменение параметра не влияет на внешнюю переменную; чтобы менять внешние переменные, нужны адреса (урок 10).
- Локальные переменные живут только в своей функции; `static` локальные сохраняют значение между вызовами; глобальных — поменьше.
- У рекурсии обязательно есть условие остановки; каждый вызов занимает место на стеке, и слишком глубокая рекурсия переполняет его.

### Задание 5: Что выведет программа

```c
#include <stdio.h>

void swap(int a, int b) {
    int t = a;
    a = b;
    b = t;
}

int counter(void) {
    static int n = 0;
    n += 10;
    return n;
}

int main(void) {
    int x = 1, y = 2;
    swap(x, y);
    printf("%d %d\n", x, y);
    counter();
    counter();
    printf("%d\n", counter());
    return 0;
}
```

<details>
<summary>Ответ и разбор</summary>

`swap` меняет местами только копии, поэтому `x` и `y` не меняются: `1 2`. `n` в `counter` — `static`, поэтому каждый вызов прибавляет 10 к прошлому значению: после первых двух вызовов 20, третий возвращает 30. Вывод: `1 2` и `30`.
</details>

<!-- exercise: prototype -->
### Задание 6: Зачем прототипы?

- чтобы функции работали быстрее
- компилятор C читает сверху вниз, поэтому перед вызовом функции, определённой ниже, прототип должен сообщить ему имя функции, её параметры и тип результата
- прототип — это определение функции, после него тело уже не нужно
- прототипы нужны только функциям `void`

<details>
<summary>Ответ и разбор</summary>

Прототип позволяет компилятору проверить число и типы аргументов, как только он видит вызов. Можно и просто поставить определение функции выше вызова — тогда прототип не нужен.
</details>

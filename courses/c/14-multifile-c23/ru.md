## 14.1 Зачем разбивать на файлы

До сих пор каждая программа была одним файлом. В настоящих проектах десятки тысяч и миллионы строк: в одном гигантском файле никто не разберётся, а изменение одной строки потребует перекомпилировать всё. Поэтому программу делят по назначению на **модули**: модуль — это файл `.c` (реализация) плюс файл `.h` (интерфейс).

Вот небольшой проект из трёх файлов. Учебная программа запускает по одному файлу за раз, поэтому пробуйте их в новой папке на своём компьютере (команда компиляции — в разделе 14.3).

```c norun
// geometry.h — «интерфейс» модуля: сообщает другим, что модуль умеет
#ifndef GEOMETRY_H
#define GEOMETRY_H

typedef struct {
    double x;
    double y;
} Point;

double distance(Point a, Point b);
double triangle_area(Point a, Point b, Point c);

#endif
```

```c norun
// geometry.c — «реализация» модуля
#include <math.h>
#include "geometry.h"

static double cross(Point o, Point a, Point b) {    // static: используется только в этом файле
    return (a.x - o.x) * (b.y - o.y) - (a.y - o.y) * (b.x - o.x);
}

double distance(Point a, Point b) {
    return hypot(a.x - b.x, a.y - b.y);
}

double triangle_area(Point a, Point b, Point c) {
    return fabs(cross(a, b, c)) / 2;
}
```

```c norun
// main.c — использует модуль
#include <stdio.h>
#include "geometry.h"

int main(void) {
    Point a = {0, 0}, b = {4, 0}, c = {0, 3};
    printf("AB = %.1f\n", distance(a, b));
    printf("площадь = %.1f\n", triangle_area(a, b, c));
    return 0;
}
```

- **В заголовках (`.h`) — только объявления**: прототипы функций, определения типов (`struct`, `typedef`, `enum`), макросы, объявления переменных с `extern`. Кто хочет пользоваться модулем, подключает его заголовок через `#include`.
- **В исходных файлах (`.c`) — определения**: тела функций и определения глобальных переменных. Исходный файл подключает и свой собственный заголовок, чтобы компилятор проверил, что объявления и определения совпадают.
- `#include "geometry.h"` в **двойных кавычках** сначала ищет в текущей папке; `#include <stdio.h>` в **угловых скобках** ищет только в системных каталогах заголовков.

## 14.2 Защита от повторного включения, `static` и `extern`

### Защита от повторного включения

`#include` на самом деле просто **вставляет содержимое заголовка** на своё место. Если `.c`-файл (косвенно) подключит `geometry.h` дважды, `Point` будет определён дважды, и компилятор пожалуется: `redefinition of ...`. Три строки в начале и в конце заголовка выше — это **защита от повторного включения** (include guard):

```c norun
#ifndef GEOMETRY_H      // если GEOMETRY_H ещё не определён...
#define GEOMETRY_H      // ...определяем его и обрабатываем то, что дальше
/* содержимое заголовка */
#endif                  // во второй раз GEOMETRY_H уже определён, и всё пропускается
```

Она нужна в каждом заголовке; имя макроса обычно — имя файла заглавными буквами. Многие компиляторы понимают и более короткое `#pragma once`, которое делает то же самое (но не входит в стандарт C).

### `static`: закрытая часть модуля

Вне функции `static` означает «**видно только в этом файле**». `cross` выше — вспомогательная функция внутри `geometry.c`; с `static` другие файлы её не видят, и она не конфликтует с одноимёнными функциями в других местах. Это очень похоже на «private» в объектно-ориентированных языках: заголовок публикует интерфейс, а `static` — детали реализации.

(Учтите: `static` у локальной переменной **внутри** функции означает другое — её значение сохраняется между вызовами, как в уроке 7.)

### `extern`: общая глобальная переменная

Если действительно нужна глобальная переменная, общая для нескольких файлов, объявите её с `extern` в **заголовке**, а определите **ровно в одном** исходном файле:

```c norun
// config.h
extern int verbose;           // объявление: переменная определена где-то ещё

// config.c
#include "config.h"
int verbose = 0;              // определение: только в одном месте
```

Если же написать `int verbose = 0;` прямо в заголовке, каждый подключивший его `.c`-файл получит своё определение, и компоновка завершится ошибкой `multiple definition of 'verbose'`. И как всегда: глобальных переменных — как можно меньше.

## 14.3 Компиляция, компоновка и ошибки компоновки

Чтобы скомпилировать многофайловую программу в терминале, перечислите все файлы `.c`:

```bash
gcc -std=c23 -Wall -Wextra -g main.c geometry.c -o app -lm
./app
```

(До GCC 14 пишите `-std=c2x`. `-lm` подключает математическую библиотеку с `hypot` и `fabs`.) Эта одна команда на самом деле выполняется в несколько шагов:

```text
main.c ──препроцессор──▶ раскрыты #include и макросы ──компиляция──▶ main.o ─┐
                                                                             ├──компоновка──▶ app (исполняемый файл)
geometry.c ──препроцессор──▶ ...                     ──компиляция──▶ geometry.o ─┘   ↑ плюс стандартная библиотека
```

1. **Препроцессор** обрабатывает все строки, начинающиеся с `#`: вставляет заголовки, раскрывает макросы, выполняет условную компиляцию.
2. **Компиляция** переводит каждый `.c`-файл **по отдельности** в машинный код — получается объектный файл (`.o`). Компилируя `main.c`, компилятор знает только прототип `distance`, но не её тело.
3. **Компоновка** (линковка): компоновщик соединяет все `.o`-файлы и стандартную библиотеку, сопоставляя каждый вызов функции с её определением.

Поэтому ошибки бывают двух видов: **ошибки компиляции** (синтаксис и типы, с указанием файла и строки) и **ошибки компоновки** (всё скомпилировалось, но при сборке определения не нашлось или их оказалось несколько):

| Ошибка компоновки | Причина |
|-------------------|---------|
| `undefined reference to 'distance'` | `geometry.c` не попал в команду компиляции; или опечатка в имени; или есть только прототип без тела |
| `multiple definition of 'verbose'` | **определение** переменной или функции попало в заголовок, подключённый в нескольких `.c`-файлах |
| `undefined reference to 'sqrt'` (в некоторых системах) | не хватает `-lm` |

Раздельная компиляция окупается: изменили только `geometry.c` — перекомпилировать нужно только его и заново скомпоновать; в больших проектах это огромная экономия времени. Инструменты сборки ниже делают это автоматически.

## 14.4 Инструменты сборки: Make и CMake

Набирать длинные команды компиляции каждый раз надоедает. **Make** читает файл `Makefile` и пересобирает только изменившееся:

```makefile
CC = gcc
CFLAGS = -std=c2x -Wall -Wextra -g

app: main.o geometry.o
	$(CC) main.o geometry.o -o app -lm

main.o: main.c geometry.h
	$(CC) $(CFLAGS) -c main.c

geometry.o: geometry.c geometry.h
	$(CC) $(CFLAGS) -c geometry.c
```

Наберите в терминале `make`, и он соберёт `app`. Каждое правило — это «цель: зависимости», а строка под ним (отступ **обязательно табуляцией**) — команда, создающая цель; она выполняется, только если какая-то зависимость новее цели.

Большие проекты обычно используют **CMake**, который создаёт файлы сборки для разных систем и компиляторов (включая Visual Studio в Windows):

```cmake
cmake_minimum_required(VERSION 3.20)
project(geometry C)
set(CMAKE_C_STANDARD 23)
add_executable(app main.c geometry.c)
target_link_libraries(app m)
```

Затем выполните `cmake -B build` и `cmake --build build`. (В Windows уберите последнюю строку: математические функции там не требуют отдельной библиотеки.)

## 14.5 Препроцессор

### Макросы с параметрами и их ловушки

`#define` умеет не только константы, но и «макросы с параметрами». Однако макрос — это всего лишь **текстовая подстановка**, а не функция, и ошибиться очень легко:

```c
#include <stdio.h>

#define SQUARE_BAD(x) x * x
#define SQUARE(x) ((x) * (x))           // скобки вокруг каждого параметра и всего результата
#define MAX(a, b) ((a) > (b) ? (a) : (b))

static inline int square(int x) {       // вариант получше: inline-функция
    return x * x;
}

int main(void) {
    printf("%d\n", SQUARE_BAD(1 + 2));  // превращается в 1 + 2 * 1 + 2, то есть 5!
    printf("%d\n", SQUARE(1 + 2));      // ((1 + 2) * (1 + 2)) = 9
    printf("%d\n", MAX(3, 7));          // 7
    printf("%d\n", square(1 + 2));      // 9: функция сначала вычисляет аргумент
    return 0;
}
```

- **Заключайте в скобки** каждый параметр макроса и всё выражение.
- Аргументы могут вычисляться дважды: `MAX(i++, j)` увеличит `i` два раза.
- Поэтому, где можно, используйте функции — `static inline` работают так же быстро, а типы проверяются; константы, где можно, задавайте через `const` или `constexpr`, а не `#define`.

### Условная компиляция и отладочный вывод

```c
#include <stdio.h>
#include <assert.h>

#define DEBUG 1

int average(const int a[], int n) {
    assert(n > 0);                       // утверждение: n должно быть положительным, иначе программа остановится с отчётом
    long sum = 0;
    for (int i = 0; i < n; i++) {
        sum += a[i];
    }
#if DEBUG
    printf("[отладка] %s, строка %d: sum = %ld\n", __func__, __LINE__, sum);
#endif
    return (int)(sum / n);
}

int main(void) {
    int data[] = {3, 5, 10};
    printf("среднее: %d\n", average(data, 3));
    return 0;
}
```

- `#if` / `#ifdef` / `#else` / `#endif` решают, **какой код будет скомпилирован**. Так оформляют отладочный код и код для конкретной операционной системы (`#ifdef _WIN32`).
- `__FILE__`, `__LINE__` и `__func__` дают имя файла, номер строки и имя функции — удобно для отладочного вывода.
- **`assert(условие)`** (`<assert.h>`): если условие ложно, выводит файл, строку и условие и аварийно завершает программу. Это проверка того, что «не должно случиться никогда», — отличный способ самоконтроля. Для итоговой сборки компилируйте с `-DNDEBUG`, и все `assert` исчезнут. Попробуйте заменить `average(data, 3)` на `average(data, 0)`.

## 14.6 C23: современный C

Стандарт C пересматривают раз в несколько лет: C89, C99, C11, C17 и теперь **C23**. Этот курс использует C23 с первого урока (параметр `-std=c2x`; новые компиляторы понимают и `-std=c23`). Вот его основные новшества в одном месте:

```c
#include <stdio.h>

constexpr int MAX_PLAYERS = 4;                   // константа времени компиляции, годится как длина массива
enum Color : unsigned char { RED, GREEN, BLUE }; // задаём базовый тип перечисления

[[nodiscard]] int checked_half(int x, bool *ok) {   // [[nodiscard]]: результат нельзя игнорировать
    *ok = (x % 2 == 0);
    return x / 2;
}

int main(void) {
    int scores[MAX_PLAYERS] = {};            // {}: пустая инициализация, всё нули
    auto total = 0;                          // auto: тип выводится из начального значения (здесь int)
    int *p = nullptr;                        // nullptr: настоящая константа нулевого указателя
    bool ok = false;                         // bool, true и false теперь ключевые слова
    int million = 1'000'000;                 // разделители разрядов
    int flags = 0b1010'0101;                 // двоичные литералы
    typeof(million) copy = million;          // typeof: тип выражения
    static_assert(sizeof(int) >= 4);         // проверка при компиляции (в C23 сообщение можно опустить)
    enum Color c = BLUE;

    int half = checked_half(10, &ok);
    printf("%d %d %d %d\n", scores[0], total, half, ok);
    printf("%d %d %d\n", million, flags, copy);
    printf("p %sнулевой указатель, c занимает %zu байт\n", p == nullptr ? "" : "не ", sizeof c);
    return 0;
}
```

| Возможность | Что значит |
|-------------|------------|
| `bool`, `true`, `false` | теперь ключевые слова, `<stdbool.h>` не нужен |
| `nullptr` | константа нулевого указателя, безопаснее `NULL` (который может быть просто целым 0) |
| `constexpr` | константы времени компиляции: безопаснее `#define`, полезнее `const` |
| `auto`, `typeof` | вывод типа компилятором и тип выражения |
| пустая инициализация `{}` | `int a[10] = {};` обнуляет всё |
| `0b1010`, `1'000'000` | двоичные литералы, разделители разрядов |
| `[[nodiscard]]`, `[[maybe_unused]]`, `[[deprecated]]` | стандартные «атрибуты», помогающие компилятору находить проблемы |
| `enum E : тип` | задать базовый целый тип перечисления |
| `static_assert(условие)` | проверка при компиляции; сообщение необязательно |
| `<stdckdint.h>` | `ckd_add(&r, a, b)` и др.: целочисленная арифметика с обнаружением переполнения |
| `<stdbit.h>` | битовые функции вроде `stdc_count_ones` |
| `#embed "file.bin"` | встроить содержимое файла прямо в массив |
| `strdup`, `memccpy` | теперь часть стандартной библиотеки |

(Последние строки — самые новые: `<stdckdint.h>` и `<stdbit.h>` требуют GCC 14 или новее, а `#embed` — GCC 15 или Clang 19. Если компилятор жалуется, что не знает `nullptr`, `bool` и т. п., он слишком стар: обновитесь до GCC 13+ или Clang 16+.)

## 14.8 Итоги

- Модуль = `.h` (объявления: прототипы, типы, макросы, `extern`) + `.c` (определения); исходный файл подключает свой заголовок.
- В каждом заголовке — защита от повторного включения (`#ifndef X_H` / `#define X_H` / `#endif` или `#pragma once`).
- `static` на уровне файла делает функции и переменные закрытыми; общие глобальные переменные объявляют `extern` в заголовке и определяют в одном исходном файле.
- Компиляция состоит из препроцессора, компиляции и компоновки; `undefined reference` и `multiple definition` — ошибки компоновки.
- Несколько файлов компилируют так: `gcc main.c geometry.c -o app`; сборку автоматизируют Make или CMake.
- Макросы — текстовая подстановка: скобки вокруг параметров и результата, а лучше функции и `constexpr`; `#if` — условная компиляция, `assert` — для того, что не должно случиться.
- C23: `bool`, `nullptr`, `constexpr`, `auto`, `typeof`, `{}`, `0b`, разделитель `'`, атрибуты, `static_assert` и другое.

### Задание 1: Модуль «стек»

Учебная программа запускает по одному файлу, поэтому в этом задании три части модуля собраны в одном файле: интерфейс (прототипы), реализация и использование. Допишите четыре функции в части реализации, используя `static`-массив `items` и счётчик `top`, чтобы получился **стек** (последним пришёл — первым ушёл): `stack_push` кладёт число (если стек полон — игнорирует); `stack_pop` снимает и возвращает последнее положенное число или -1, если стек пуст; `stack_empty` сообщает, пуст ли стек; `stack_size` возвращает число элементов. `main` уже написана; она читает команды вида `push x`, `pop` и `size`.

```text
Пример ввода: push 3 push 5 pop size pop pop
Пример вывода:
5
1
3
-1
```

<details>
<summary>Подсказка</summary>

`push`: `if (top < STACK_MAX) { items[top] = value; top++; }`. `pop`: если пусто — вернуть -1, иначе `top--; return items[top];`. Сам `top` и есть число элементов.
</details>

Прочитайте целое `x` (0 ≤ x < 2³¹) и выведите через пробел его двоичную запись (без ведущих нулей; для нуля — `0`) и количество единиц в ней.

Пример ввода: 10
Пример вывода: 1010 2

<details>
<summary>Подсказка</summary>

Проверяйте биты от старшего к младшему: `for (int bit = 30; bit >= 0; bit--)`, бит берётся как `(x >> bit) & 1`, а нули до первой единицы пропускаются. Можно и наоборот: собрать биты от младшего через `x % 2` и `x / 2` в массив, а затем вывести его задом наперёд.

### Задание 4: Что выведет программа

```c
#include <stdio.h>

#define DOUBLE_BAD(x) x + x
#define DOUBLE(x) ((x) + (x))
#define SQUARE_BAD(x) x * x

int main(void) {
    printf("%d\n", 3 * DOUBLE_BAD(2));
    printf("%d\n", 3 * DOUBLE(2));
    printf("%d\n", SQUARE_BAD(1 + 2));
    return 0;
}
```

<details>
<summary>Ответ и разбор</summary>

Макросы — просто текстовая подстановка. `3 * DOUBLE_BAD(2)` превращается в `3 * 2 + 2`, то есть 8; `3 * DOUBLE(2)` — в `3 * ((2) + (2))`, то есть 12; `SQUARE_BAD(1 + 2)` — в `1 + 2 * 1 + 2`, то есть 5. Вывод:

```text
8
12
5
```
</details>

### Задание 5: Ошибка компоновки

Функция `area` определена в `geometry.c`; `main.c` подключает `geometry.h` и вызывает `area`. Компиляция командой `gcc main.c -o app` завершается ошибкой `undefined reference to 'area'`. Почему?

- в `geometry.h` нет защиты от повторного включения
- в команду компиляции не попал `geometry.c`
- в `main.c` нет `#include <stdio.h>`
- `area` нужно было сделать `static`

<details>
<summary>Ответ и разбор</summary>

`undefined reference` — ошибка компоновки: `main.c` скомпилировался, но при компоновке определения `area` нет, потому что `geometry.c` вообще не участвовал. Команда должна быть `gcc main.c geometry.c -o app`. Если сделать `area` `static`, она спрячется внутри `geometry.c` — и будет ровно та же ошибка.
</details>

### Задание 6: Защита от повторного включения

Зачем нужны `#ifndef GEOMETRY_H` / `#define GEOMETRY_H` в начале заголовка и `#endif` в конце?

- чтобы заголовок быстрее компилировался
- чтобы один и тот же заголовок не включался в исходный файл несколько раз, из-за чего типы и прочее определялись бы повторно
- чтобы в заголовке можно было писать определения функций
- чтобы другие файлы не могли подключать этот заголовок

<details>
<summary>Ответ и разбор</summary>

В первый раз `GEOMETRY_H` ещё не определён: содержимое обрабатывается, и `GEOMETRY_H` определяется; при любом следующем включении условие `#ifndef` ложно и всё пропускается, так что ошибки `redefinition` не будет.
</details>
